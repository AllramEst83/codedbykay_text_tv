## What texttv.nu's API page says (read 2026-10-05)

From `https://texttv.nu/blogg/texttv-api`: every client must send a unique `app` value (done: `texttv_android`), or risks stopping working. It documents the single-page endpoint `/api/get/{n}`, a range `/api/get/{a}-{b}`, a JSONP form, and `includePlainTextContent=1`. It says **nothing** about rate limits, polling or caching, nothing about terms or attribution, and it has **no** endpoint for "last updated" or "has this page changed": the only hint is a changelog line about being told when a newer version of a page exists. So: be courteous (auto-refresh is off by default and no faster than every 30 s; nothing is read while the app is in the background), and re-read this page before publishing (I-14). Not yet done: re-fetching the live pages and diffing them against `test/fixtures/` (the build sandbox could not reach the site).

## Tier 1

- [x] **I-1. Persistent cache, stale-while-revalidate.** Done: `PageDiskCache`/`FilePageDiskCache` keep the raw answer per page (200 max, in the cache folder), `LiveTextTvRepository` falls back to it offline and `cached()` lets the screen show it at once; the note uses our save time, not `date_updated_unix`. Original description: Today the cache is in memory for 5 min, so a cold start with no network shows an error even for a page read a minute ago. Keep pages on disk (SQLite/drift or files; JSON per page), show the cached page immediately, refresh behind it, and say "offline, updated 14:32" using `date_updated_unix` (the client does not read it today). Evict by age/size.
- [x] **I-2. Remember where you were.** Last page, part and history survive restarts; a cold start opens where you left off. Done: `TextTvSession` + `SessionStore`.

## Tier 2

- [ ] **I-12. A proper teletext face and rendering.** Press Start 2P is a game font and the code stretches its glyphs upright (`stretch`, up to 2×) to imitate teletext's tall characters. Evaluate a real teletext font (e.g. Bedstead; check its licence) and drop the stretch. Also: `_paintCell` builds a `TextPainter` for every non-blank character on every repaint (about 900 per page); cache glyph paragraphs per (character, style, size) or draw each row as one paragraph, and wrap the page in a `RepaintBoundary`. Not urgent (a page rarely repaints), but it is the obvious cost if animation or zoom gestures are added.
- [-] **I-13. Sub-page cycling.** Declined by the user: not wanted. (Original idea: a "play" toggle that rotates sub-pages, and a `1/3` indicator on the page.)
- [ ] **I-14. Legal, attribution and store basics.** The content is SVT's, relayed by texttv.nu's author. Before publishing: read their terms, add an About screen crediting SVT Text and texttv.nu, keep sending an `app` id that identifies this app (their API page asks for it), consider contacting the site's author about a published app's extra load, and write a privacy statement ("no account, no analytics; the page number you ask for is sent to texttv.nu"). Add a data-safety note for a Play listing. Do this before deciding between sideloading and the store; either way, create a real release keystore first (see [android.md](android.md)).
  - [x] **Done so far:** an ABOUT panel at the end of the settings page (SVT Text credit, "not made or approved by SVT or texttv.nu", what is and is not sent) in both languages; `PRIVACY.md` with a data-safety note; texttv.nu publishes no terms, attribution rules or rate limits (its API page and site were read 2026-10-05; there are no /om, /integritet or /villkor pages); the `app` id is sent.
  - [ ] **Still to do (needs the owner):** a release keystore; deciding sideload vs store; optionally contacting texttv.nu's author about a published app's load.
- [x] **I-15. Parser robustness.** Done as a canary rather than a bigger fixture set: `tool/check_live.dart` reads pages 100, 101, 104, 300, 377, 400 and 700 live (one second apart) through the app's own client and fails if any is not in broadcast, fails to read, or falls back to plain text; `.github/workflows/live-canary.yml` runs it weekly (and on demand). Read 2026-10-05: all seven pages read with colours. The block-graphics decoder depends on the site's GIF bytes (it rebuilds them to match CRC-32s), so a change there shows up as a fallback or a missing logo; the existing test that every picture on the saved pages is known covers the fixtures. Not done, on purpose: fetching all 800 pages as fixtures (800 requests to a small site for little gain over the canary).
- [x] **I-16. Accessibility.** Done: the page on show has a node of its own (`PageSemantics`: `Page 377` / `Page 377, part 1 of 2`, a live region so a change is announced), in teletext and reader mode; each link in a teletext row is a button node of its own (the row painter's `semanticsBuilder`, at least 48 wide, named by its page) that TalkBack can focus and activate, while the row still reads as its text; the rows' own tap action is hidden. Targets were already >= 48 dp. Not verified with TalkBack on a phone.
- [ ] **I-17. Golden test with the font loaded.** `flutter test` has no pixel font, so layout regressions are caught by geometry assertions only. Load the bundled font with `FontLoader` in a test and add a golden of a real page.
